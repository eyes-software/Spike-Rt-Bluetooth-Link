# テスト

BluetoothLink の検証用プロジェクトです。いずれも**自己完結したコンソールアプリ**で、
実行すると各項目の `PASS` / `FAIL` を出力し、失敗件数を終了コードで返します。

テストフレームワークは使っていません。UI・負荷・無線を実際に動かして確かめる性質のものが多く、
フレームワークに載せると扱いづらいためです（純粋なロジックのみ `CoreTests` に集めています）。

## 一覧

| プロジェクト | 内容 | 実機 | 所要時間 |
| --- | --- | --- | --- |
| `CoreTests` | 区切り (フレーミング)、16 進変換、Pybricks のプロトコル変換、ファイル書き出し | 不要 | 数秒 |
| `UiTests` | プリセット切り替えに伴う画面状態、コントロールの配置、リサイズ追従 | 不要（画面は必要） | 約 1 分 |
| `LoadTests` | 高頻度受信時に UI が応答し続けるか、記録の欠落を把握できているか | 不要（画面は必要） | 約 30 秒 |
| `ScanTests` | BLE デバイス検索が逐次表示されるか、検索中に操作できるか | **Bluetooth アダプター必須** | 約 20 秒 |

`UiTests` / `LoadTests` / `ScanTests` はフォームを実際に表示して操作するため、
デスクトップセッション上で実行してください（CI のヘッドレス環境では動きません）。

## 実行

```bash
dotnet run --project tests/CoreTests -c Release
```

```bash
dotnet run --project tests/UiTests -c Release
```

```bash
dotnet run --project tests/LoadTests -c Release
```

```bash
dotnet run --project tests/ScanTests -c Release
```

すべて成功すると最後に `ALL PASS` と出ます。失敗した項目は `FAIL` 行に理由が付きます。

## 注意点

- `LoadTests` は実際の受信ハンドラをダミーセッションから高頻度で叩きます。判定は
  **BLE の現実的なレート (2,000 / 10,000 件/秒)** に対して行い、全力投入は CPU が飽和して
  測定値が安定しないため参考値の記録にとどめています。
- `ScanTests` は周囲の BLE 機器を検出できることが前提です。電波の届く範囲に機器が
  1 台もない環境では「2 秒以内に最初の 1 件が出る」が失敗します。
- テストは内部フィールドへリフレクションでアクセスします。`MainForm` のフィールド名を
  変えた場合はテスト側の修正が必要です。
